# Анализ критических проблем памяти и оценка потребления

## 1️⃣ КРИТИЧЕСКАЯ ПРОБЛЕМА: Бесконечные потоки (fetcher.py)

### Текущее потребление:
```
Stack потока:                    ~2 MB × 3 потока = 6 MB
requests.Session() pool:         ~2 MB (в каждом потоке на соединения)
Кешированные JSON ответы:        
  - News (Fetcher._run_news):    ~1-10 MB (список новостей)
  - Queue data (Fetcher._run_queue): ~500 KB × 5 сек = 100 KB
  - Online status:               ~50 KB

Cache соединений (Connection Pool):  
  - каждый requests.Session по умолчанию держит 10 соединений в pool
  - Per соединение: ~50-100 KB
  - TOTAL: ~1.5-3 MB на session

ИТОГО: 15-25 MB минимум на ПОСТОЯННО работающих потоков
При долгой сессии (8 часов): могут быть утечки +5-10 MB/час = 40-80 MB дополнительно
```

### Проблема:
- 3 потока работают **бесконечно**, нет способа их остановить
- при закрытии лаунчера они продолжают работать в фоне
- Connection pool растет со временем

### Решение:
```python
# После инициализации Fetcher нужно добавить:
self._stop_event = threading.Event()
self._threads = []

# И переделать _run_* методы:
def _run_queue(self):
    while not self._stop_event.is_set():  # Проверка флага остановки
        if not self.in_game:
            try:
                # ... код ...
            except:
                pass
            self._stop_event.wait(5)  # wait вместо sleep (можно прервать)
        else:
            self._stop_event.wait(2)

# При выходе из приложения:
def stop(self):
    self._stop_event.set()
    for thread in self._threads:
        thread.join(timeout=2)
```

## 2️⃣ КРИТИЧЕСКАЯ ПРОБЛЕМА: mc_timer без остановки (main.py)

### Текущее потребление:
```
QTimer объект в памяти:           ~100 KB
Callback функция (_check_mc_state): ~50 KB

ПРОБЛЕМА: Работает КАЖДЫЕ 2 СЕКУНДЫ при открытом лаунчере
Каждый вызов:
- win32gui.EnumWindows() - перебор всех окон (~1 MB временно)
- Строковые сравнения
- Update UI

За час: 1800 вызовов × потенциальные утечки = может быть 50-100 MB
```

### Главная проблема:
- при закрытии лаунчера таймер **НЕ ОСТАНАВЛИВАЕТСЯ**
- после `app.exec()` завершения он продолжает работать в фоне
- `pygame.mixer.stop()` в `_check_mc_state` вызывается каждые 2 сек ненужно

### Решение:
```python
def exit_launcher(self):
    try:
        self.mc_timer.stop()  # ✅ Добавить остановку
        self.ui.media_player.stop()
        pygame.mixer.stop()
        self.close()
```

## 3️⃣ КРИТИЧЕСКАЯ ПРОБЛЕМА: Растущие словари модов (ui.py + main.py)

### Текущее потребление:

**Сценарий:** Пользователь делает 5 поисков модов (каждый возвращает 54 результата)

```
mod_buttons словарь:
  - 1 кнопка QPushButton: ~300-500 KB (включая стили, иконки, connections)
  - 54 кнопки × 5 поисков × 500 KB = 135 MB ❌

mod_cards словарь:
  - 1 карточка QFrame: ~200 KB  
  - 54 × 5 × 200 KB = 54 MB ❌

mod_labels словарь:
  - 1 label: ~100 KB
  - 54 × 5 × 100 KB = 27 MB ❌

news_data список:
  - Обновляется каждые 2 минуты
  - 1 новость JSON: ~5-20 KB
  - 30 новостей × 8 часов (240 обновлений) × 20 KB = 144 MB ❌

shaders_data и resourcepacks_data: +50-100 MB

ИТОГО за сессию: 410+ MB утечек!! 🔴
```

### Главная проблема:
```python
def update_mod_cards(self, mods):
    for mod in mods:
        button = QPushButton(...)
        self.mod_buttons[mod['slug']] = button  # ❌ Добавляется, НЕ УДАЛЯЕТСЯ
        self.mod_cards[mod['slug']] = card      # ❌ РАСТЕТ ВЕЧНО
        self.mod_labels[mod['slug']] = label    # ❌ РАСТЕТ ВЕЧНО
```

Из-за этого память не освобождается даже при удалении сложного виджета!

### Решение:
```python
def clear_mod_cache(self):
    # Очистить виджеты перед новым поиском
    for button in self.mod_buttons.values():
        button.deleteLater()
    for card in self.mod_cards.values():
        card.deleteLater()
    for label in self.mod_labels.values():
        label.deleteLater()
    
    self.mod_buttons.clear()
    self.mod_cards.clear()
    self.mod_labels.clear()

# Вызывать перед новым поиском
def setup_mods_search(self):
    self.clear_mod_cache()  # ✅ Очистить старые данные
    # ... создать новые ...
```
